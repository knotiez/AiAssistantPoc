# DB 지연 장애 대응 Runbook

## 1. 목적
본 문서는 데이터베이스(DB) 지연으로 인해 서비스 응답 속도가 저하되는 경우,
이를 신속하게 인지하고 적절한 대응을 수행하기 위한 기준을 정의한다.

본 Runbook은 애플리케이션 배포 장애 Runbook과 함께 참조될 수 있으며,
원인 구분이 명확하지 않은 경우 병행 검토가 필요하다.

---

## 2. 적용 범위
- 주요 트랜잭션 DB (PostgreSQL, MySQL)
- 읽기/쓰기 쿼리를 사용하는 API 서버
- 배치 작업 중 발생하는 DB 부하 상황

외부 API 호출로 인한 지연은 본 문서의 직접적인 적용 대상이 아니다.

---

## 3. 주요 증상

### 3.1 API 응답 지연
- 전체 API 응답 시간이 증가
- 특정 API가 아닌 전반적인 지연 양상

### 3.2 DB 커넥션 대기 증가
- DB 커넥션 풀 대기 시간 증가
- active connection 수 증가

### 3.3 쿼리 실행 시간 증가
- 특정 쿼리 또는 다수 쿼리의 실행 시간 증가
- 동일 쿼리의 실행 시간이 평소 대비 현저히 증가

---

## 4. 기본 확인 절차

### 4.1 DB 상태 확인
다음 항목을 우선 확인한다.

- 현재 active connection 수
- idle connection 수
- 평균 쿼리 실행 시간
- slow query 발생 여부

### 4.2 애플리케이션 로그 확인
- DB timeout 관련 에러 로그
- 커넥션 풀 exhaustion 로그
- 최근 배포 이력 여부

> 최근 배포가 동시에 진행된 경우,  
> 배포 장애 Runbook을 함께 참조한다.

---

## 5. 장애 판단 기준

다음 조건 중 하나 이상에 해당할 경우 DB 지연 장애로 판단할 수 있다.

- 평균 쿼리 실행 시간이 **평소 대비 2배 이상** 증가
- DB 커넥션 대기 시간이 **1초 이상** 지속
- DB CPU 사용률이 **80% 이상** 지속

단, 일시적인 트래픽 증가로 인한 현상은 제외할 수 있다.

---

## 6. 배포 장애와의 구분 기준

다음 조건을 기준으로 배포 장애와 DB 지연 장애를 구분한다.

| 항목 | DB 지연 장애 | 배포 장애 |
|----|------------|---------|
| 응답 지연 범위 | 전체 API | 특정 API |
| 최근 배포 여부 | 무관 | 직후 발생 |
| DB 메트릭 | 이상 징후 있음 | 정상일 수 있음 |

구분이 어려운 경우 두 Runbook을 동시에 참조한다.

---

## 7. 대응 절차

### 7.1 즉각 조치
- 트래픽 급증 여부 확인
- 불필요한 배치 작업 중단 검토

### 7.2 원인 분석
- slow query 분석
- 최근 쿼리 변경 이력 확인
- 인덱스 미적용 여부 확인

### 7.3 롤백 판단
DB 지연이 배포 직후 발생했고,
쿼리 변경이 포함된 배포인 경우에 한해 롤백을 고려할 수 있다.

---

## 8. 후속 조치
- 쿼리 튜닝 또는 인덱스 추가 검토
- 커넥션 풀 설정 재검토
- 장애 원인 문서화

---

## 9. 참고 사항
- 본 Runbook은 일반적인 기준을 제공하며,
  상황에 따라 운영 담당자의 판단이 우선될 수 있다.
- 세부 기준은 운영 환경에 따라 다를 수 있다.
