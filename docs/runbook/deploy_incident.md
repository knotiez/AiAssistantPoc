# 배포 중 장애 대응 Runbook

## 1. 목적
본 문서는 서비스 배포 과정에서 발생할 수 있는 장애를 신속하게 인지하고,
서비스 영향을 최소화하기 위한 기본 대응 절차를 정의한다.

본 Runbook은 운영팀과 개발팀이 공통으로 참조하는 문서이며,
상황에 따라 세부 절차는 담당자의 판단에 따라 조정될 수 있다.

## 2. 적용 범위
- API 서버 배포
- 백엔드 배치 서버 배포
- API Gateway 설정 변경

프론트엔드 단독 배포 장애는 본 문서의 적용 대상에서 제외한다.

## 3. 주요 장애 유형

### 3.1 배포 직후 응답 지연
- 평균 응답 시간 증가
- 특정 API에서만 지연 발생

### 3.2 5xx 에러 증가
- 전체 요청 대비 5xx 비율 상승
- 특정 인스턴스에서 집중 발생하는 경우 포함

### 3.3 트래픽 미수신
- 일부 인스턴스에서 트래픽이 유입되지 않음
- 로드밸런서 설정 오류 가능성

## 4. 기본 대응 절차

### 4.1 배포 중단
- CI/CD 파이프라인을 즉시 중단한다.
- 이미 배포된 인스턴스는 트래픽 차단 여부를 판단한다.

### 4.2 로그 및 모니터링 확인
다음 항목을 우선 확인한다.
- API Gateway Access Log
- 애플리케이션 Error Log
- 최근 10분 이내 메트릭

필요 시 이전 배포 시점과 비교한다.

### 4.3 롤백 판단 기준

다음 조건 중 하나라도 충족할 경우 롤백을 고려한다.

- 5xx 에러 비율이 **3% 이상** 지속
- 평균 응답 시간이 **2초 이상**으로 5분 이상 유지
- 주요 비즈니스 API 오류 발생

단, 트래픽 증가로 인한 일시적 지연은 제외할 수 있다.

## 5. 롤백 이후 조치
- 롤백 완료 후 정상 동작 여부 확인
- 장애 원인 분석을 위한 로그 보존
- 필요 시 장애 보고서 작성

## 6. 참고 사항
- DB 지연 또는 외부 API 장애가 의심될 경우 별도 Runbook을 참조한다.
- 본 문서는 최신 기준이며, 과거 문서와 상충될 수 있다.
